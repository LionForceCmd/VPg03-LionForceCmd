# Домашнее задание VPg03. Память в LangChain и других фреймворках

## 1. Мои задачи

Я хочу использовать LLM в повседневных задачах:
- личный помощник по финансам: учёт расходов, сводки по категориям, напоминание о лимите;
- помощник по учёбе: вопросы по конспектам, лекциям и PDF-материалам курсов;
- ответы на типовые вопросы клиентов для небольшого интернет-магазина или сервиса: по FAQ, условиям доставки и возврата.

Во всех трёх случаях нужны память (кто пользователь, о чём говорили раньше), доступ к моим документам и данным и вызов простых функций (посчитать, найти, отправить).

## 2. Выбранные фреймворки

### LangChain (+ LangGraph)
**Особенности:** агенты, tools через `@tool`, структурированный вывод (`dataclass`), память через checkpointer (`InMemorySaver`, `SqliteSaver`), много интеграций (OpenAI, Anthropic, Postgres, Pinecone). LangGraph даёт граф состояний: узлы, условные рёбра, чекпоинты.

**Где пригодится у меня:**
- Помощник по финансам: tools читают CSV или таблицу расходов, считают суммы по категориям, сравнивают с лимитом пользователя (лимит берётся из контекста `user_id`).
- Чат-бот поддержки: память по `thread_id` хранит диалог с каждым клиентом, а tools проверяют статус заказа или ищут ответ в FAQ.
- Структурированный ответ (`dataclass`) удобен, когда результат нужно сразу передать в приложение, таблицу или другой сервис без парсинга текста.

### LlamaIndex
**Особенности:** индексация внешних данных (документы, PDF, базы, API), много адаптеров и коннекторов, сильный RAG. Слабее там, где нужен интерактивный агент с постоянным контекстом.

**Где пригодится у меня:**
- Помощник по учёбе: загрузить конспекты, PDF и записи уроков, потом задавать вопросы и получать ответ с опорой на мои материалы.
- База знаний для поддержки: индексировать FAQ, условия доставки и возврата, инструкции, чтобы бот отвечал по реальным документам, а не придумывал.

### Haystack (рассматривал, но не выбрал)
Надёжен для поиска и QA, с Elastic и Hugging Face. Но менее гибок для динамических агентов, а RAG-часть у меня закрывает LlamaIndex.

### Semantic Kernel (не подходит)
Хорош для интеграции с Azure и экосистемой Microsoft. Моим задачам эта экосистема не нужна, вне неё фреймворк тяжеловесен.

## 3. Итог

| Фреймворк | Подходит | Для чего у меня |
|---|---|---|
| LangChain/LangGraph | да, основной | агент с tools и памятью: финансы, поддержка клиентов |
| LlamaIndex | да, вспомогательный | RAG по конспектам, PDF и FAQ |
| Haystack | нет | дублирует LlamaIndex |
| Semantic Kernel | нет | нужен Azure/Microsoft-стек |

## 4. Дополнительное задание: агент со своим tool

Папка `agent/`. Агент собран по примеру из урока (LangChain `create_agent`, модель `gpt-4o-mini`, системный промпт, `InMemorySaver`, `thread_id`, `ResponseFormat` через `dataclass`, контекст `user_id`).

**Мой tool:** `summarize_expenses(file_name)` читает CSV с личными расходами и возвращает общую сумму, суммы по категориям и самую большую трату. Второй tool, `get_user_budget`, по аналогии с `get_user_location` из урока берёт месячный лимит пользователя из контекста.

Проверка без API-ключа (фейковая модель, `python test_offline.py`): агент вызвал tool для `expenses.csv` и получил итог 18309.80 руб. (больше всего на продукты, 8230.80), затем в том же `thread_id` через контекст `user_id=1` получил лимит 20000 руб. В памяти треда осталось 10 сообщений, то есть память работает. С реальной моделью (`python main.py`) запуск не делался: нужен ключ OpenAI/proxyapi в `.env`.
